# Mission: Solve problems from scratch, not from snippets

## Why
Andrei can wire together existing code snippets into working systems, but rarely
derives a solution end-to-end on his own without hints or copy-paste. He wants to
become an engineer who can sit down in front of a blank editor, face an unfamiliar
problem, and reason his way to a working solution independently.

## Success looks like
- Given a new, unfamiliar problem, produce a correct solution **without** searching
  for hints or snippets first.
- Verbalise a repeatable problem-solving method and actually apply its steps under pressure.
- Trace a problem by hand on concrete examples, extract the pattern, then translate
  that pattern into code — in that order.
- Look at his own working code (e.g. Run-Length Encoding) and explain *how it could
  have been derived*, not just *that it works*.

## Constraints
- Learns through his own repo (`ts-knowledge-base`) — TypeScript/JS, algorithm practice.
- Already comfortable with the language and syntax; the gap is process, not vocabulary.
- Prefers short, hands-on lessons tied to real code he's writing.

## Out of scope (for now)
- Advanced/exotic algorithms (graphs, DP) — the method comes first, on simple problems.
- Interview-specific optimisation drills — this is about genuine capability, not LeetCode speed.
- Learning new frameworks or the language itself.
